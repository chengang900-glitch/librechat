# LibreChat Portal 顶栏与品牌元素定制设计

**日期：** 2026-09-01  
**基线：** LibreChat v0.8.7，`enterprise-ai/portal-v1`  
**范围：** 仅调整 Portal 启用时的顶栏、用户菜单位置和聊天页页脚。

## 目标

1. 四个一级应用菜单相对整个页面水平居中。
2. 四个菜单增加与语义一致的图标。
3. 将 LibreChat 左下角用户头像及原有用户菜单迁移到顶栏右上角。
4. Portal 启用时不显示聊天页底部任何页脚内容，包括 LibreChat 标识、版本/更新信息、隐私政策和服务条款。
5. 用独立文件记录所有 LibreChat 定制点，供后续版本升级时迁移。

## 布局设计

顶栏使用三列 CSS Grid：

- 左列：企业品牌名，左对齐。
- 中列：四个一级菜单，作为内容宽度列。
- 右列：用户头像，右对齐。

左右列均使用 `minmax(0, 1fr)`，确保中列相对页面中心对齐，不受品牌文字或用户头像宽度影响。在小屏上允许中间菜单水平滚动，不破坏桌面端的真正居中。

## 菜单图标

复用项目已有的 `lucide-react`，不新增依赖：

| 菜单     | 图标         |
| -------- | ------------ |
| AI 助手  | `Brain`      |
| 数据中心 | `BarChart3`  |
| 文档中心 | `Files`      |
| 应用中心 | `LayoutGrid` |

图标为 18px，使用 `aria-hidden="true"`，菜单的可访问名称仍由文字提供。保留现有激活下划线、字体、颜色和新页签行为。

## 用户菜单迁移

顶栏复用原有 `AccountSettings` 功能，不复制设置、我的文件、归档对话、帮助、快捷键和退出登录逻辑。

`AccountSettings` 增加顶栏布置变体，仅调整菜单弹出方向、样式和定位。Portal 启用时，`UnifiedSidebar` 不再渲染左下角头像；Portal 关闭时保持 LibreChat 原有行为。

## 页脚处理

`Chat/Footer` 保留上游实现，但在已认证启动配置表明 Portal 开启时直接不渲染。这样同时去除产品标识、更新提示、隐私链接和条款链接，又使 `PORTAL_ENABLED=false` 时恢复上游默认页脚。

本次不修改登录页的独立 `Auth/Footer`，因为 Portal 配置只向已登录用户下发，且用户指定的是 LibreChat 主页底部产品标识。

## 升级迁移记录

新建 `docs/portal/CUSTOMIZATIONS.md`，按定制项记录：

- 用户目标和实际行为。
- 涉及的上游文件和 Portal 文件。
- 关键函数、组件和配置开关。
- 上游版本升级后的迁移步骤。
- 构建、类型检查、功能和回归验证清单。

该文件只记录已实现定制，不包含密码、Token、Cookie 或 `.env` 内容。

## 验证标准

1. 桌面宽度下，四个菜单中心与页面水平中心一致。
2. 四个菜单均显示正确图标和文字，内外部跳转行为不变。
3. 右上角头像能打开完整原生用户菜单，左下角不再显示头像。
4. 聊天页底部不显示任何页脚元素。
5. Portal 关闭时，左下角用户菜单和原生聊天页脚恢复。
6. 变更文件定向测试、TypeScript 检查、ESLint 和生产构建通过。
7. 新镜像部署后 `/readyz` 返回 200，`/portal/apps` 内部路由可达，原有 Portal API 验收不回退。

## 非目标

- 不修改 LibreChat 对话、模型、Agent、MCP、文件或 OIDC 核心逻辑。
- 不修改 Metabase 和 Seafile 的页面或认证。
- 不新增顶栏可配置编辑器。
- 不把用户菜单内的功能拆成新组件或第二套逻辑。
- 不处理外网 NAT/端口映射。
